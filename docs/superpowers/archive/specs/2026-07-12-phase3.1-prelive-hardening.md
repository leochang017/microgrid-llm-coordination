# Phase 3.1 — Pre-Live-Run Hardening (Design Spec)

**Date:** 2026-07-12 · **Status:** approved (Leo, 2026-07-12) · **Plan:** `docs/superpowers/plans/2026-07-12-phase3.1-prelive-hardening.md`

## Why this phase exists

A 2026-07-12 adversarially-verified full-repo review (9 specialized reviewers + up to 3
independent verifiers per finding; 55 unique confirmed findings, 2 refuted) ran against tag
`phase3-infra-complete`. The infrastructure core held up — physics conservation, LP-ceiling
validity, RNG determinism, and zero-LLM-control isolation were all verified clean — but the
findings cluster on exactly the surfaces the **budget-gated live runs** depend on: the
defector experiment's validity, crash-resume of paid API calls, artifact safety, and the
provenance/instrumentation the paper will quote.

**Phase 3.1 gates all live spend.** No live LLM run may launch before this phase is tagged
`phase3.1-complete`. Live-run execution itself is Phase 3.2
(`docs/superpowers/plans/2026-07-12-phase3.2-live-runs.md`).

## Decisions locked at approval (do not re-litigate in execution)

1. **Repo visibility is settled: PUBLIC.** Leo decided 2026-07-12 that
   github.com/leochang017/microgrid-llm-coordination stays public (it has been public from
   day 1). The advisor's earlier private-until-draft preference is superseded; flag the
   decision to him in the next update email. Consequence: **security checks are a standing
   rule** (see CLAUDE.md Workflow preferences) — no secrets in any commit, `/security-review`
   before each phase tag.
2. **Defector realizations:** `wrapper` = channel corruption only (control condition);
   `prompt` = selfish system prompt only; `both` = both. The wrapper is applied **only**
   when realization ∈ {wrapper, both}. This matches both the Phase 2 and Phase 3 specs;
   the shipped code applied the wrapper unconditionally (review F3).
3. **Commitment TTL wording, not behavior, changes:** a commitment is serviceable on its
   creation tick plus the following 2 (3 `act()` windows). Prompts/spec text said "2 ticks";
   fix the words, keep `expires_t_idx = last_t_idx + 2` (review F39).
4. **REQUEST fan-out splits the need** across the top-3 recipients (`need/len(top)` each,
   deduped per peer) rather than sending the full need to each (review F17).
5. **OFFERs no longer consume react LLM calls** — only REQUESTs enter `pending_react`.
   OFFER receipt still lands in the memory stream (review F14).
6. **Sonnet ablation model id:** `claude-sonnet-5` (pinned in a committed YAML, not typed
   at launch).
7. **`critical_load_frac: [0.2, 0.6]`** is added to the live-run YAML family only
   (`haves_havenots_solar__llm*`), never to the golden-pinned base scenarios. This changes
   the household draw for those YAMLs — that is expected and re-pinned in Task 21.
8. **Number re-derivation protocol:** any task that changes settled behavior re-derives
   affected numbers **in the same commit** via the exact commands in the task, updates
   pins/docs, and records old → new in the progress-log row. Golden pins for
   `haves_havenots` / `haves_havenots_solar` (no_coord, rr, LP) are expected to stay
   **byte-identical** through every task except where a task explicitly says otherwise —
   if they move unexpectedly, STOP and investigate; do not re-pin to make a test pass.

  tightened in T18 for the winter/heatwave scenarios; no quoted number changes.

  SoC + load observation noise, which is implemented and swept. Re-add only with a spec.
