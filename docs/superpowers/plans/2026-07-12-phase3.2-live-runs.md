## The launch pattern (memorize the shape)

```bash
python -m scripts.run \
  --scenario configs/scenarios/<CELL>.yaml \
  --reference-cell <CELLNAME> --seed <SEED>
```

- `--reference-cell` writes to `reference_runs/<scenario>/llm_agent/<CELLNAME>__seed<SEED>/` — a STABLE directory, so a crashed/rate-limited run is resumed by RERUNNING THE IDENTICAL COMMAND: every already-paid response replays from the run-local cache at $0 (Phase 2.7 needed 4 attempts; the cache absorbed the cost). Never launch live with a bare `--out-dir runs` (fresh timestamp = cold cache = re-pay on crash).
- One cell at a time. No parallel live runs (shared rate limits; interleaved spend is unauditable).
- Expect 45–90 min wall per 24 h Haiku cell (Phase 2.8: 64 min for 12 h).

### Post-run verification (EVERY cell, before the next one)

```bash
RUN=reference_runs/<scenario>/llm_agent/<cell>__seed<seed>
python - <<'EOF'
import json, pathlib, sys
run = pathlib.Path("<RUN>")   # substitute
s = json.loads((run / "summary.json").read_text())
checks = {
    "messages.jsonl exists": (run / "messages.jsonl").exists(),
    "llm_cache non-empty": any((run / "llm_cache").iterdir()),
    "cost recorded": s["llm_cost_usd_estimated"] > 0,
    "counters present": "commitments_made" in s["llm_call_counts_detailed"],
    "failure modes recorded": "failure_modes_active" in s,
    "parse failures sane (<5%)": s["policy_parse_failures"] <= 0.05 * max(1, s["llm_call_counts"]["reflect_plan"]),
}
print(json.dumps({k: bool(v) for k, v in checks.items()}, indent=2))
print("served", s["served_load_fraction"], "gini", s["gini_welfare"],
      "cost $", round(s["llm_cost_usd_estimated"], 2))
sys.exit(0 if all(checks.values()) else 1)
EOF
```

Then commit the cell (`reference_runs/...` is git-tracked; the repo is public by Leo's decision — the security rule applies: `git diff --cached | grep -icE 'sk-ant|bearer '` → 0 before every push).

### Why they are immune — the mechanism (code trace, 2026-07-16)

`failure_modes` has **exactly one application site in the codebase**: `llm_agent.prepare` (`sim/strategies/llm_agent.py:125-145`), which `llm_fallback` also routes through (`llm_fallback.py:54-64`). Nothing else reads it. `sim/engine.py:235,324` only *serialize* it.

- **round_robin** never touches the message layer: it defines only `decide_transfers`, so `run.py:105` hands it `message_bus=None`, and it reads engine ground-truth SoC directly (`round_robin.py:40,48`). Immune to `comm` (no messages to drop), to `noise` (never reads the perturbed channel), to `defectors` (no prompts).
- **lp_optimal** is an oracle over ground-truth profiles with perfect foresight and explicitly ignores the comm graph (`lp_optimal.py:115-120` + module docstring). Immune by construction.
- **The five YAMLs are physically identical apart from the `failure_modes` block** — so for round_robin and lp_optimal all five configs are literally *the same simulation*. That is why they are bit-identical rather than merely close.
- **control under `comm` (−12.4):** INFORMs are emitted last (`llm_agent.py:331-334`), so `per_tick_budget: 2` starves them (`protocol.py:120-139`); empty `peer_beliefs` then hits the early return at `agent.py:813-814` → **no discretionary sharing at all**. The damage is *eligibility collapse*, not degraded reasoning.
- **control under `defectors` (+0.0) is structural, by design (P3.1 T5):** `use_wrapper=False` makes `maybe_corrupt` the identity, and the selfish system prompts are built but `llm_disabled=True` means no LLM call ever reads them (`agent.py:386,607`).

**⚠️ `summary.json`'s `failure_modes_active` means CONFIGURED, not applied.** A round_robin summary in the comm cell truthfully reports `per_tick_budget: 2` while no comm code ran. Do not read it as evidence of exposure — check the strategy. (Caveat now in `sim/logging.py`'s docstring.)

**⚠️ Do NOT report "noise helps the control".** The +1.3 is one seed's realization luck, not a mechanism. Both channels were measured directly (2026-07-16): the load clamp `max(0, L·(1+0.15z))` binds only at z < −6.67 (p≈1e-11) for a **+0.048%** bias — three orders of magnitude too small to matter. The SoC clamp `clip(S + 0.10·cap·z, 0, cap)` *is* biased (a full 10 kWh battery reads 9.60, an empty one reads 0.40) but it is **mean-reverting**: haves look less full → share less, have-nots look less empty → request less. Both *reduce* sharing, so it could only hurt. Nothing in either channel can systematically help; +1.3 sits well inside the ~16-pt cross-seed spread.

## Failure playbook

- **429 / OAuth 401 mid-run:** wait for the limit window, rerun the IDENTICAL command; cache replays paid calls. Three consecutive 401s → re-mint the token, do not edit code.
- **Crash mid-run:** rerun identical command (stable `--reference-cell` dir). Verify `cache_hits` in the relaunch's summary ≈ calls made before the crash.
- **Numbers look insane** (served < control − 0.05 or > LP): stop spending; run the mock replay of the same cell (`--strategy llm_fallback`) and diff configs; suspect a `--set` typo first (they hard-error now, but check `config.json` provenance in the run dir).
- **A YAML edit is needed mid-campaign:** any prompt/YAML change invalidates cross-cell cache comparability — finish the current stage first, note the change in the log table, never mix architectures within a stage.
